## Code Quality & Style

- Write clean, well-documented code following established conventions
- Use meaningful, consistent variable and function names
- Include comments only where logic isn't self-evident
- Follow separation of concerns and appropriate design patterns
- Consider performance implications; optimize critical paths
- Validate all inputs; follow secure coding practices
- Write comprehensive tests for new functionality with descriptive test names

## Documentation

- Document all public APIs and interfaces with usage examples where appropriate
- Keep documentation up to date with code changes
- ALWAYS read markdown files (CHANGELOG.md, README.md, PROJECT_STATUS.md, etc.) to understand project context before making modifications

## Architecture

- Design for maintainability — avoid premature abstractions
- Three similar lines of code is better than a premature abstraction
- Don't add features, error handling, or validation beyond what was asked
- Don't design for hypothetical future requirements
